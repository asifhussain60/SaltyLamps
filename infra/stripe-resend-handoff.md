## How the integration works

### Stripe checkout and order processing

`salty-lamps-site/functions/api/checkout.js` reads prices and stock from D1, creates a GBP embedded Checkout Session using `STRIPE_SECRET_KEY`, and returns the matching publishable key to the browser. `functions/api/checkout/verify.js` verifies a returning session. `functions/api/webhook.js` verifies the raw event with `STRIPE_WEBHOOK_SECRET`, records paid orders, releases expired/failed checkouts, and reconciles refunds. The durable order email work is queued from the paid-order flow. The protected `test.saltylamps.co.uk` webhook address redirects to Cloudflare sign-in, so it cannot prove that Stripe can deliver to the eventual public webhook.

`wrangler.staging.toml` sets `STRIPE_TEST_ONLY=1`, which rejects a live Stripe secret or live webhook event. `wrangler.live.toml` omits that switch, binds the same database and the R2 image bucket, and points `SITE_URL` at `https://www.saltylamps.co.uk`. The live deploy preflight rejects sandbox flags or plain-text secrets in its configuration. The live Stripe destination must target `https://www.saltylamps.co.uk/api/webhook` and subscribe to these seven events: `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `refund.created`, `refund.updated`, and `refund.failed`. As of this review, the live destination and `www` payment-method domain were not registered. The proposed restricted-key permissions and payment-method decisions are detailed in migration step 7; they are derived from code calls and still need live validation.

### Resend delivery and replies

`salty-lamps-site/functions/lib/mailer.mjs` reads `RESEND_API_KEY` from the Pages environment and the sender, recipients, and `email_enabled` switch from D1 settings. It calls the Resend email API and records sent, failed, or deliberately skipped results. Paid-order and refund messages also use `functions/lib/durable-email.mjs` so their intent survives a retry. The 11 templates are editable in the administrator. The test-send action can bypass `email_enabled` to preview a draft, but it **cannot** bypass `MAIL_DRY_RUN`, a missing key, or a missing sender. Customer order replies use the public contact address at the retained Zoho mailbox. Receipt of the earlier direct-test reply at that business mailbox was not verified.

Resend is configured for **sending only**; the existing Zoho MX records and mailbox remain in service. The DNS evidence is in `infra/resend-domain-setup-2026-09-26.json` and the owner-key evidence is in `infra/resend-owner-key-verification-2026-09-27.json`. The latter records the key identifier and delivery test without containing its value. `d1/staging/production-email-settings.sql` is a staged proposal, not an automatic migration and not proof of the real database's current settings.
